# PLAN_APPROVAL_COLLEGE 前端测试清单

流程定义来源:
- [audit_step_def-data.sql](../database/seeds/audit_step_def-data.sql#L44)

补充说明:
- 当前 clean seed 中，学院类 Plan 的默认上级职能部门创建者是教务处。
- 因此终审环 `战略发展部审核人审批` 使用战略发展部终审账号测试。

默认密码: `admin123`

## 一、流程说明

步骤如下（2026-11-22 起为四节点，删「分管职能部门校领导」审批环；学院侧只设「填报人」与「审核人」两个席位）:
1. 填报人提交
2. 学院审核人审批（席位：审核人）
3. 分管职能部门负责人审批（席位：归口职能部门审核人）
4. 战略发展部审核人审批（席位：战略发展部负责人，终审）

注：step_no 不重排（定义 id 14 永久空缺），审批进度按步骤实例顺序展示。

推荐测试账号:
- 发起人: `jisuanji_report`（填报人）
- 第二步审批人: `jisuanji_audit1`（学院审核人）
- 第三步审批人: `jiaowu_audit1`（分管职能部门负责人）
- 第四步审批人（终审）: `zlb_final1`（战略发展部审核人）

## 二、发起操作

1. 使用 `jisuanji_report / admin123` 登录。
2. 进入 `计划管理`。
3. 找到计算机学院对应的草稿 Plan。
4. 点击 `提交审批` 或 `发起审批`。
5. 弹窗中点 `确认`。
6. 记录 Plan 名称。

预期结果:
- 第一步自动完成。
- 第二步待办分配给 `jisuanji_audit1`。

## 三、第二步审批

1. 退出后使用 `jisuanji_audit1 / admin123` 登录。
2. 进入 `审批中心` 或 `我的待办`。
3. 找到该 Plan。
4. 点击 `通过`。
5. 输入 `流程4第二步通过`。
6. 点击确认。

预期结果:
- 第二步通过。
- 第三步待办分配给 `jiaowu_audit1`（归口职能部门审核人席位）。

## 四、第三步审批

1. 退出后使用 `jiaowu_audit1 / admin123` 登录。
2. 进入 `审批中心` 或 `我的待办`。
3. 找到同一条 Plan。
4. 先完成指标评级（第 3 环属强制全评门禁，未评级不能通过）。
5. 点击 `通过`。
6. 输入 `流程4第三步通过`。
7. 点击确认。

预期结果:
- 第三步通过。
- 第四步（终审）待办分配给 `zlb_final1`。

## 五、第四步审批（终审）

1. 退出后使用 `zlb_final1 / admin123` 登录。
2. 进入 `审批中心` 或 `我的待办`。
3. 找到同一条 Plan。
4. 点击 `通过`。
5. 输入 `流程4终审通过`。
6. 点击确认。

预期结果:
- 流程结束（全程仅 4 环，无「分管校领导」待办出现）。
- Plan 状态变为已审批。

## 六、驳回测试

建议至少测两种:

场景 A: 第二步驳回
1. `jisuanji_audit1` 点 `驳回`。
2. 输入 `流程4第二步驳回`。

预期:
- 流程退回发起人。

场景 B: 终审环驳回
1. `zlb_final1` 点 `驳回`。
2. 输入 `流程4终审驳回`。

预期:
- 流程退回学院侧。
- `jisuanji_audit1` 或上一步相关账号重新可见待办。

## 七、前端检查点

- 第二步待办应只落到学院审核人。
- 第三步待办应只落到归口职能部门审核人。
- 第四步（终审）待办应落到战略发展部账号；全程不再出现「分管职能部门校领导」待办。
- 审批进度/历史卡按步骤实例动态渲染，只显示 4 环。
- 第三环未完成评级时无法通过（评级门禁生效）。
- 全过程不需要手工选择审批人。
